# 医药雷达 V3.0 产品需求文档

副标题：公共云生产版  
状态：长期规划，须经合规和上线评审后启动  
目标用户：中国境内公开用户及行业从业者  
运行方式：中国大陆公共云为主，境外采集节点补充  
核心后端：Spring Boot + MySQL

## 1. 版本目标

V3.0将经过V1内容价值验证和V2私有运行验证的产品，升级为任何用户均可访问的公开服务。

本版本重点不是简单把V2端口暴露到公网，而是补齐：

- 稳定的境内访问；
- 公开内容合规和版权治理；
- 公网安全；
- 可观察、可备份、可恢复的生产运维；
- 匿名浏览和可控注册；
- 境内用户服务与境外来源采集解耦；
- 随用户增长扩展的架构边界。

## 2. 上线门禁

以下事项任何一项未完成，不得公开上线：

- 产品运营主体和责任人明确；
- 域名、云资源和数据存放区域明确；
- 完成ICP备案或依法所需许可；
- 完成互联网新闻信息服务适用性专项评估；
- 完成版权、转载、摘要和来源授权评估；
- 隐私政策、用户协议、免责声明和投诉渠道完成审核；
- 数据收集清单、保留期限和删除流程明确；
- 完成安全测试、备份恢复和应急演练；
- 完成内容审核规则及责任人配置；
- 明确哪些功能P0开放、哪些功能保持关闭。

本PRD不构成法律意见。Codex不得把技术实现结果描述为“已合规”，只能记录所需控制和待人工确认事项。

## 3. 产品定位

公开版定位为：

> 对国内外监管公告、临床试验、科研论文元数据、企业正式披露等公开信息进行结构化整理的医药行业情报工具。

不得宣传为具有新闻采编资质的媒体，不得通过改名规避实际业务可能适用的监管规则。

## 4. 范围

### 4.1 P0公开测试版

- 无需登录的公开只读浏览；
- 今日必读、最新、分类、搜索和详情；
- 来源、原始链接、生成标识和更正记录；
- 境内云上的Vue PWA和Spring Boot API；
- MySQL生产数据库、Flyway和备份；
- 国内采集与境外采集解耦；
- 管理后台和分级审核；
- CDN/WAF或等效边界防护；
- 限流、缓存、监控、日志和告警；
- SEO仅覆盖允许公开的页面；
- 隐私、协议、版权投诉和内容纠错入口；
- 灰度发布和快速回滚。

### 4.2 P1注册与个性化

- 用户注册、验证、登录和注销；
- 收藏、关注、多设备同步；
- 每日/每周摘要；
- 重要事件提醒；
- 企业、药品和疾病主题页；
- 用户数据导出和账号删除；
- 管理员用户治理。

### 4.3 P2增强功能

- 同一事件多来源对照；
- 政策版本差异；
- 临床试验时间线；
- 企业/药品关系图谱；
- 行业趋势和专题报告；
- 团队空间或付费功能（需单独立项和合规评估）。

### 4.4 明确不做

- 在线问诊、处方和个体化用药建议；
- 股票推荐、收益承诺和自动交易；
- 用户自由发帖和评论区；
- 未授权新闻全文、论文全文或图片镜像；
- 绕过付费墙、登录、验证码、robots或地区限制；
- 未经验证的社交媒体消息自动公开；
- 在用户请求链路中实时抓取国外网站。

## 5. 用户与角色

### VISITOR

- 无需登录浏览允许公开的内容；
- 搜索、筛选和查看来源；
- 本地收藏可作为未登录降级；
- 不可访问管理和个人同步数据。

### USER（P1）

- 管理自己的收藏、关注、提醒和账号；
- 导出或删除自己的数据；
- 不可发布内容。

### EDITOR

- 审核、编辑事实摘要、分类、标签和更正说明；
- 不可管理系统密钥和用户角色。

### ADMIN

- 来源、用户角色、系统配置、内容撤回和审计；
- 高风险操作需要二次确认；
- 不得直接查看用户密码、Token或不必要个人数据。

## 6. 生产架构

### 6.1 逻辑架构

```text
中国用户
   ↓
境内DNS/CDN/WAF
   ↓
Nginx/Ingress
   ├─ Vue 3静态资源
   └─ Spring Boot API
          ├─ MySQL
          ├─ Redis（达到触发条件后启用）
          └─ 对象存储（仅合法资产、导出和备份）

国外官方来源
   ↓
境外采集Worker/GitHub Actions
   ↓ 签名批次或鉴权导入API
境内入库与审核
```

### 6.2 初始部署

V3.0公开测试可从单区域、单应用实例开始，但必须：

- 数据库使用独立持久卷或托管MySQL；
- 备份复制到不同故障域；
- 应用容器无状态；
- 上传和导出不依赖容器本地磁盘；
- 配置、密钥和镜像与代码分离；
- 预留横向扩展接口。

### 6.3 Redis启用条件

以下任一发生时再引入Redis：

- 单实例无法满足缓存和会话需求；
- 需要多实例共享Session；
- 热点查询对MySQL造成持续压力；
- 需要可靠的分布式任务锁或短期队列。

不得仅因“生产环境通常需要”而提前引入。

## 7. 功能需求

### V3-F-001 匿名公开访问

- 公开内容无需登录；
- 管理、审核和个性化接口必须鉴权；
- 搜索引擎只能抓取允许索引的内容；
- 被撤回、拒绝或待审核内容不得通过ID枚举访问；
- API响应不包含内部备注、采集日志和授权信息。

### V3-F-002 公共搜索

- 搜索标题、摘要、实体、药品和疾病；
- 支持组合筛选和稳定分页；
- 输入长度、频率和复杂度受限；
- 热门查询缓存；
- 无结果时推荐栏目或纠正明显拼写；
- 不根据用户敏感健康信息建立画像。

### V3-F-003 内容页面

详情页必须展示：

- 原始事实和中文结构化摘要；
- 来源、原作者（适用时）、原标题、原始链接；
- 发布时间和系统采集时间；
- 生成内容标识及人工核验状态；
- 相关实体和主题；
- 更正、更新、撤回记录；
- 版权/纠错投诉入口；
- 医疗和投资免责声明。

### V3-F-004 公开内容准入

只有满足以下条件的记录才可公开：

- 来源在公开白名单；
- `legalBasis`已配置；
- Schema校验通过；
- 原始链接和来源可追溯；
- 不含未经授权全文或图片；
- 高风险分类满足人工审核规则；
- 生成摘要通过事实一致性检查；
- 不含禁止公开字段。

### V3-F-005 境外采集

- 境外Worker只连接允许的官方API、RSS和已授权来源；
- 不向境外Worker发送用户个人信息；
- 采集结果先进入隔离区；
- 批次包含来源、时间、Schema版本、哈希和签名；
- 境内导入端执行白名单、重放、防篡改和大小校验；
- Worker故障不影响用户读取已有数据；
- 原文可访问状态由后台检查，不在每个用户点击时探测。

### V3-F-006 国内采集

- 境内Worker采集国内监管、医院、科研、交易所和企业公告；
- 遵守来源访问频率和使用条款；
- HTML解析器变化触发健康告警和人工检查；
- 政策文件保留正式文号、发布机关和生效日期字段；
- 重要信息优先链接原始发布机关。

### V3-F-007 内容审核与更正

- 来源与事件类型决定审核级别；
- 公共卫生、安全、召回、处罚、重大临床结果默认进入人工审核；
- 编辑修改必须保留前后差异和原因；
- 更正不静默覆盖，用户可见更正时间；
- 紧急撤回应立即停止对外展示，同时保留内部审计记录；
- 管理员可对来源批量暂停发布。

### V3-F-008 注册与账号（P1）

- 注册方式在实施前由产品所有者选择，不默认绑定国外身份服务；
- 邮箱/手机号等验证信息最小化保存；
- 支持密码重置、设备Session管理和全部退出；
- 用户可下载自己的收藏、关注和账号数据；
- 用户发起注销后按政策删除或匿名化；
- 不将用户关注的疾病直接用于广告或敏感画像。

### V3-F-009 订阅与提醒（P1）

- 用户可关注企业、药品、疾病、政策和事件；
- 默认采用站内摘要或用户主动订阅的渠道；
- 推送频率可控，可一键退订；
- 召回、安全等标签不等同于医疗建议；
- 通知只包含最小信息，点击后进入受控详情页。

### V3-F-010 管理后台

包括：

- 内容审核和批量处理；
- 来源健康、失败率和延迟；
- 采集/导入批次；
- 用户和角色；
- 投诉、纠错和版权请求；
- 发布、撤回和更正；
- 系统健康、版本、迁移和备份；
- 审计日志检索和导出。

高风险操作使用再次认证或双人复核策略，具体由上线评审决定。

### V3-F-011 API治理

- API保持`/api/v1`；
- 发布OpenAPI文档，但生产环境隐藏内部管理Schema；
- 所有列表有最大页大小；
- 写接口支持幂等键（适用时）；
- 全局Problem Details错误格式；
- 请求ID贯穿边界、应用和日志；
- 匿名、登录和管理接口采用不同限流策略；
- 不在错误响应中暴露实现细节。

### V3-F-012 缓存与降级

- CDN缓存带内容哈希的前端资源；
- 公开Article GET可使用短时缓存和ETag；
- 内容撤回必须使相关缓存失效；
- API故障时可提供最近一次静态只读快照；
- 页面明确显示快照时间；
- 不缓存用户私有响应到公共缓存。

### V3-F-013 监控和告警

至少监控：

- HTTP吞吐、延迟、错误率；
- JVM、容器、CPU、内存和磁盘；
- MySQL连接、慢查询、容量；
- 采集成功率、来源延迟、队列积压；
- 登录失败和限流事件；
- 证书、域名、备份和任务状态；
- 用户页面合成探测。

告警必须有责任人、严重级别、静默规则和处理手册。

### V3-F-014 投诉与反馈

- 页面提供内容纠错、版权投诉和一般反馈入口；
- 自动生成关联文章ID、URL和提交时间；
- 收集信息最小化；
- 后台可分派、处理和关闭；
- 处理动作与内容更正/撤回关联；
- 对外公布可执行的联系渠道。

在V2表基础上新增或扩展：

```text
content_revision
content_complaint
publication_policy
legal_source_record
notification_subscription
notification_delivery
user_consent
account_deletion_request
security_event
```

要求：

- 内容公开状态有数据库约束或统一发布服务保护；
- 审计日志只追加，按规定期限归档；
- 不在分析表复制不必要个人标识；
- 所有删除/匿名化任务可重试并有结果记录。

## 9. 安全要求

### 边界安全

- 仅开放80/443，80跳转HTTPS；
- 管理入口可追加IP/VPN/身份网关限制；
- WAF、速率限制和基础DDoS防护；
- 安全响应头、CSP、HSTS和合理CORS；
- 数据库和Actuator不暴露公网。

### 应用安全

- 使用成熟身份认证机制；
- CSRF、XSS、SQL注入、SSRF、越权和文件上传专项测试；
- 采集器防SSRF：协议、域名、IP解析和重定向均校验；
- 管理操作最小权限；
- 密钥轮换和失效流程；
- 依赖、镜像和代码扫描；
- 严重漏洞修复时限由上线规范确定。

### 数据安全

- 传输加密；
- 备份加密；
- 密钥不与备份同存；
- 数据库账号按用途分离；
- 生产数据不得直接复制到开发环境；
- 日志脱敏并限制访问。

## 10. 合规和内容要求

上线前必须由专业人员确认：

- 互联网新闻信息服务许可是否适用；
- 境外来源翻译、摘要、转载和链接方式是否符合要求；
- ICP、公安联网备案或其他手续；
- 版权授权和投诉处理；
- 隐私、个人信息和Cookie；
- 算法推荐或生成合成内容相关义务；
- 医疗健康信息边界；
- 上线地区和云服务商附加要求。

工程必须支持而不是替代这些判断：

- 来源白名单和合法依据字段；
- 人工审核和发布开关；
- 生成内容标识；
- 更正、撤回和审计；
- 用户协议/隐私版本与同意记录；
- 数据导出、删除和投诉处理。

## 14. 容量触发点

不要提前微服务化。满足以下条件再评估拆分：

- 采集任务明显影响用户API；
- 数据量使单库检索无法达到SLO；
- 不同模块需要独立扩容或发布；
- 团队规模和故障域需要明确服务边界。

优先顺序：索引优化 → 缓存 → 异步任务 → 读写分离 → 独立搜索 → 服务拆分。

## 15. Codex实施顺序

### Epic 0：合规与上线门禁

- 只创建检查清单、开关和证据记录；
- 等待人工结论；
- 未通过时不执行公开发布。

### Epic 1：云基础与环境隔离

- staging/production；
- 域名、HTTPS、密钥、镜像和数据库；
- 备份和基础监控。

### Epic 2：公开只读体验

- 匿名API、缓存、SEO和静态降级；
- 内容公开字段过滤；
- 公开页面移动端优化。

### Epic 3：采集、审核与内容治理

- 境内/境外Worker；
- 隔离导入、审核、更正、撤回；
- 投诉和审计。

### Epic 4：安全与可靠性

- 限流、WAF、CSP、监控和告警；
- 安全测试、压测、故障演练和回滚。

### Epic 5：注册与个性化（P1）

- 只有P0稳定且隐私流程通过后实施；
