# 医药雷达 V2.0 产品需求文档

副标题：私有自托管协作版  
状态：规划，V1验收后启动  
目标用户：产品所有者及少量受邀朋友、同事  
建议规模：不超过6名用户  
运行方式：自有Windows/NAS/迷你主机 + Docker + Tailscale  
核心后端：Spring Boot + MySQL

## 1. 版本目标

V2.0在不购买公共云服务器的前提下，将V1个人静态工具升级为小范围、可登录、可管理、数据可同步的私有服务。

本版本验证：

1. 一台自有设备能否稳定承担采集、API、数据库和私有访问；
2. 少量用户是否需要跨设备收藏、关注和搜索；
3. 管理后台能否降低来源维护、失败处理和重点内容审核成本；
4. 国内本地采集与GitHub Actions境外补采能否形成稳定双通道。

## 2. 前置条件

只有同时满足以下条件才能进入V2：

- V1连续14天采集成功率不低于95%；
- Article/Feed契约已冻结为1.x；
- 已确定24小时运行或可接受停机的自有设备；
- 已验证设备所在网络可连接Tailscale；
- 已确定私有试用用户和设备；
- 已完成V1数据导入演练；
- 已准备MySQL备份存储位置，且不与运行盘单点共存。

## 3. 范围

### 3.1 继承V1

V1所有浏览、搜索、筛选、PWA、来源追溯和内容边界继续有效。前端仅把数据实现从`StaticArticleRepository`切换为`ApiArticleRepository`。

### 3.2 P0必须实现

- Spring Boot REST API；
- MySQL持久化与Flyway迁移；
- Docker Compose一键启动；
- Tailscale私有访问和HTTPS入口；
- 管理员创建/停用用户；
- 登录、退出、Session安全；
- 角色：ADMIN、MEMBER；
- 多设备收藏和关注同步；
- 服务端搜索、筛选和分页；
- 定时采集、任务状态和手动补采；
- GitHub Actions境外数据包导入；
- 内容审核队列和置顶；
- 来源管理和健康看板；
- 数据库备份、恢复与运行手册；
- 基础审计日志。

### 3.3 P1可以延后

- 用户个人笔记；
- 每日/每周邮件摘要；
- 专题收藏夹；
- 管理员批量修改分类；
- 简单趋势统计；
- 局域网只读应急入口。

### 3.4 本版本不做

- 无邀请的公开注册；
- 面向公网的匿名访问；
- 短信登录、微信登录和付费会员；
- 公共搜索引擎收录；
- 评论、投稿和用户发布内容；
- 高可用集群、Kubernetes或微服务拆分；
- 将Tailscale用作访问境外新闻的代理；
- 直接暴露MySQL、Actuator完整端点或管理后台到公网。

## 4. 角色与权限

### ADMIN

- 创建、停用和重置MEMBER账号；
- 配置来源启停、频率和重要度；
- 查看任务、错误和来源健康；
- 审核、修改、置顶、撤回文章；
- 执行补采、重新分类、重新摘要；
- 查看审计日志；
- 触发并验证备份。

### MEMBER

- 浏览、搜索、筛选和查看详情；
- 管理自己的收藏、关注和阅读状态；
- 查看公开给私有成员的来源信息；
- 不得访问管理接口、任务日志、其他用户数据或数据库信息。

## 5. 部署架构

```text
受邀手机/电脑
      ↓ Tailscale私有网络
Tailscale Serve（HTTPS）
      ↓ 127.0.0.1入口
Nginx
  ├─ /        Vue 3 PWA
  └─ /api     Spring Boot
                  ↓
                MySQL
```

Docker Compose服务：

- `web`：Nginx托管Vue产物并反向代理API；
- `api`：Spring Boot；
- `mysql`：MySQL 8.x；
- 可选`backup`：按计划执行备份，但必须可单独关闭。

Tailscale建议安装在宿主机，而不是第一版就容器化。Web入口仅绑定`127.0.0.1`或受控接口；数据库不映射宿主机公网端口。

## 6. 功能需求

### V2-F-001 身份认证

- 账号仅由ADMIN创建；
- 用户名或邮箱在私有范围内唯一；
- 首次登录强制修改临时密码；
- 密码使用Spring Security推荐的自适应哈希；
- 连续失败触发渐进式延迟和临时锁定；
- 登录成功后使用服务端Session Cookie；
- Cookie必须Secure、HttpOnly、SameSite=Lax；
- 所有状态修改请求必须通过CSRF保护；
- 退出后服务端Session立即失效。

验收：未登录访问API返回401；MEMBER访问管理接口返回403；Cookie中不包含明文凭据。

### V2-F-002 用户管理

- ADMIN创建、停用、启用和重置密码；
- 不允许删除最后一个ADMIN；
- 停用用户的所有Session立即失效；
- 默认最多6个活跃用户，超过时提示管理员确认部署与Tailscale计划；
- 管理页面不得显示密码哈希。

### V2-F-003 Article API

`GET /api/v1/articles`支持：

- `cursor`、`limit`；
- `q`；
- `region`、`category`、`eventType`、`diseaseArea`、`sourceTier`；
- `followedOnly`、`favoriteOnly`；
- `sort=published|importance`；
- `from`、`to`。

最大`limit`为100，默认20。所有过滤参数必须验证，错误使用Problem Details返回。

### V2-F-004 收藏、关注和阅读状态

- 收藏按用户隔离；
- 关注支持entity、drug、disease、keyword四类；
- 同一用户不得创建完全相同的关注；
- 阅读状态按文章记录；
- 首次登录可导入V1本地JSON；
- 上传前必须由用户确认，不自动读取或上传浏览器本地数据。

### V2-F-005 服务端搜索

V2 P0使用MySQL全文索引或经过验证的LIKE/前缀组合实现，不引入Elasticsearch。

要求：

- 中英文标题、摘要和实体可查；
- 结果稳定分页；
- 关键词长度和特殊字符受控；
- 慢查询记录指标但不记录敏感查询全文；
- 1万至10万文章范围内常见查询P95目标小于800ms。

### V2-F-006 定时采集

- Spring Scheduler或受控任务框架执行；
- 数据库锁保证同一任务不并发；
- 每个来源维护cursor、ETag或Last-Modified（来源支持时）；
- 任务可手动触发，但必须防重复点击；
- 失败采用有限指数退避；
- 全流程幂等；
- 任务状态写入`collection_run`和`source_run`。

### V2-F-007 国内外双通道

本地节点负责国内及可访问来源；GitHub Actions继续负责本地访问不稳定的国外官方来源。

境外数据包必须：

- 遵循V1 Feed Schema；
- 包含生成时间、schemaVersion和文件SHA-256；
- 通过HTTPS下载；
- 只接受来源白名单中的`sourceId`和域名；
- 导入前做大小、Schema、时间窗口和重复校验；
- 失败时隔离数据包，不部分写入；
- 成功后记录导入批次和数量。

不得因境外数据包失败阻塞本地来源采集。

### V2-F-008 管理后台

提供移动端可用但以桌面操作为主的管理页面：

- 待审核文章；
- 来源健康；
- 采集运行记录；
- 失败详情和重试；
- 用户管理；
- 文章编辑、置顶、撤回；
- 系统版本、数据库迁移版本和最近备份。

任何修改必须记录操作者、时间、对象、动作和变更摘要。

### V2-F-009 审核流程

状态：

```text
UNREVIEWED → AUTO_CHECKED → PUBLISHED
                     ↘ NEEDS_REVIEW
NEEDS_REVIEW → PUBLISHED | REJECTED
PUBLISHED → WITHDRAWN
```

- A级官方数据通过自动校验后可发布；
- 高风险事件（安全、召回、处罚、公共卫生）可配置为必须人工审核；
- C级线索默认不得发布；
- 被撤回内容保留审计记录，对用户显示更正/撤回说明。

### V2-F-010 来源管理

来源配置以数据库为运行态、`sources.yml`为可审查初始种子。

管理员可修改：启停、频率、超时、重要度、审核策略；不可在页面中直接填写源码或任意脚本。URL变更必须符合允许协议和域名规则。

### V2-F-011 备份与恢复

- 每日自动逻辑备份；
- 默认保留最近7个每日备份和4个每周备份；
- 备份加密或保存在受控磁盘；
- 备份结果可见但路径和凭据仅ADMIN可见；
- 每月至少一次恢复到临时数据库并校验核心表数量；
- 文档提供完整恢复步骤。

### V2-F-012 服务健康

提供有限公开到私网的健康接口：

- liveness不访问外部来源；
- readiness检查数据库和必要迁移；
- 详细Actuator端点只允许ADMIN或本机；
- 首页显示数据新鲜度，不把系统健康等同于数据新鲜度。

### V2-F-013 审计日志

记录：登录成功/失败、用户变更、来源变更、文章审核、手动任务、备份和配置变化。不得记录密码、Session、Token或完整正文。

### V2-F-014 Tailscale访问

- 只邀请已确认的个人账号；
- 用户离开测试后立即撤销共享或成员资格；
- 使用MagicDNS/HTTPS地址；
- 不配置Tailscale Funnel；
- 不做家庭整个子网路由；
- 访问策略仅允许应用HTTPS端口，非必要时不开放SSH/RDP。

## 7. 数据库要求

核心表建议：

```text
article
article_source_link
source
source_cursor
collection_run
source_run
user_account
user_session（如采用JDBC Session）
favorite
follow_rule
read_state
article_review
audit_log
import_batch
```

约束：

- `article.id`沿用V1稳定ID；
- `source_id + external_id`在可用时唯一；
- `canonical_url_hash`建立索引；
- 收藏使用`user_id + article_id`唯一约束；
- Flyway迁移必须可从空库重放；
- 生产配置禁用`ddl-auto=create/update`。

## 8. 安全与隐私

- VPN网络层和应用账号层必须同时存在；
- 默认拒绝跨域，前后端同源；
- 只通过Tailscale Serve提供HTTPS；
- 登录、搜索和管理接口设置速率限制；
- 用户输入统一校验和输出编码；
- 错误页面不显示堆栈、SQL和文件路径；
- Docker镜像使用非root用户和固定版本；
- 每次发布运行依赖漏洞扫描；
- 隐私说明明确保存用户名、收藏、关注和日志范围；
- 用户可导出并删除自己的收藏/关注数据，审计日志按安全期限保留。

## 9. 运维要求

### 启动

```text
docker compose up -d
```

执行前必须校验环境变量；首次启动执行Flyway；启动后运行健康检查。

### 停机与更新

- 更新前备份数据库；
- 拉取固定镜像标签，不使用`latest`；
- 运行迁移后执行冒烟测试；
- 失败时回滚应用镜像；数据库迁移必须提前设计向前兼容或明确恢复步骤。

### Windows宿主机

- 禁止自动休眠；
- Docker和Tailscale设置为开机启动；
- 预留磁盘空间告警；
- Windows重启后验证Compose、Tailscale Serve和定时任务恢复。

## 10. 非功能需求

| 采集成功率 | 周均≥97% |
| 数据可追溯 | 100% |
| 私有可用性 | 月度目标≥99%，不承诺商业SLA |
| 备份RPO | ≤24小时 |
| 恢复RTO | ≤4小时（人工恢复） |
| 浏览器 | iOS Safari、Android Chrome主流近期版本 |

## 12. Codex实施顺序

### Epic 1：数据库与API基础

- Flyway基线、JPA模型、Article查询API；
- Testcontainers集成测试；
- V1 JSON导入器。

### Epic 2：认证与个人数据

- Spring Security Session；
- ADMIN/MEMBER；
- 用户、收藏、关注和阅读状态。

### Epic 3：采集与管理

- 数据库任务状态；
- 双通道导入；
- 审核、来源管理和审计。

### Epic 4：容器与私网

- Compose、Nginx和环境配置；
- Tailscale Serve运行手册；
- Windows开机恢复检查。

### Epic 5：备份与验收

- 自动备份、恢复测试；
- 权限、安全、iOS/Android和重启E2E。

## 13. 完成定义

- 所有P0功能通过自动化和人工验收；
- V1数据完成可重复迁移；
- 6名以内受邀用户可通过iOS/Android使用；
- 公网无法访问应用及数据库端口；
- 备份恢复演练成功；
- 连续14天私有运行无数据损坏；
- 已记录设备停机、断网和更新流程；
- 已填写进入V3的用户量、可用性和合规需求。
