# 医药雷达 V1.0 产品需求文档

副标题：个人静态验证版  
状态：P0代码已实现，本地自动化验证通过；线上与真机验收待完成  
目标用户：产品所有者本人  
运行方式：GitHub Pages + GitHub Actions，无常驻后端服务器  
主要终端：iPhone Safari/PWA、Android Chrome/PWA

## 1. 版本目标

V1.0用最低成本验证以下核心假设：

1. 国内外医药公开信息能否稳定汇总到一个移动端入口；
2. 分类、中文标题和短摘要能否显著降低每日阅读成本；
3. “今日必读、关注、搜索、收藏”是否形成持续使用价值；
4. 不购买云服务器时，GitHub Actions定时采集和GitHub Pages静态发布是否足够稳定。

V1成功的标准不是“功能很多”，而是连续14天自动更新、来源可追溯、手机端每天可用。

## 2. 范围

### 2.1 P0必须实现

- Vue 3移动端PWA；
- 国内外官方来源定时采集；
- 静态JSON数据契约；
- 今日必读和最新新闻流；
- 新闻详情；
- 按地区、栏目、事件和来源筛选；
- 前端搜索；
- 本地收藏、稍后读和关注关键词；
- 海外信息中文标题与事实摘要的可插拔处理；
- 来源、发布时间、采集时间及原文链接；
- 去重、失败重试、数据新鲜度和来源健康状态；
- GitHub Actions自动构建、测试、采集和部署；
- iPhone及Android安装到主屏幕；
- 基础离线浏览。

### 2.2 P1可以延后

- 每日简报导出为Markdown；
- 纯前端热点词统计；
- 新闻分享卡片；
- 手动置顶配置；
- 可选LLM翻译与摘要提供器。

### 2.3 本版本不做

- Spring Boot常驻Web服务；
- MySQL、Redis或在线管理后台；
- 用户注册、登录、多设备同步；
- 评论、投稿、团队协作；
- Web Push和实时预警；
- 个性化推荐算法；
- 保存或转载第三方新闻全文；
- 微信、支付宝或原生iOS/Android应用；
- 分钟级实时更新承诺。

## 3. 用户场景

### US-V1-01 今日浏览

作为个人用户，我希望打开应用后先看到当天最重要的医药信息，以便在5分钟内完成行业速览。

### US-V1-02 定向筛选

作为个人用户，我希望按中国/海外、政策、研发、企业、医院等条件筛选，以便只阅读当前关心的内容。

### US-V1-03 关注主题

作为个人用户，我希望关注企业、药品、疾病或关键词，以便在“关注”页面快速找到相关更新。

### US-V1-04 来源核验

作为个人用户，我希望看到原始来源、时间和链接，并区分机器生成内容，以便判断可信度。

### US-V1-05 弱网阅读

作为个人用户，我希望网络短暂不可用时仍能打开最近已浏览或缓存的数据。

## 4. 信息架构

底部导航固定为：

1. 今日
2. 分类
3. 关注
4. 收藏
5. 设置

### 4.1 今日页

从上到下展示：

- 日期、问候语、数据最后更新时间；
- 数据过期或采集失败提示；
- 今日一句概览；
- 今日必读5至10条；
- 政策/安全等高重要度事件；
- 最新新闻流；
- 加载更多日期。

### 4.2 分类页

- 国内/海外快捷切换；
- 12个一级栏目；
- 地区、事件类型、疾病领域、来源级别组合筛选；
- 当前筛选条件可一键清空；
- 筛选状态写入URL查询参数，可通过浏览器返回恢复。

### 4.3 关注页

- 用户在本机创建关键词关注；
- 支持企业、药品、疾病和自由关键词；
- 展示命中数量和最近命中文章；
- 数据仅存储在IndexedDB。

### 4.4 收藏页

- 收藏/取消收藏；
- 标记已读/未读；
- 按收藏时间倒序；
- 原文章不在当前90天静态数据内时，仍保留最小快照：标题、来源、日期、链接。

### 4.5 设置页

- 安装PWA说明，按iOS/Android显示不同步骤；
- 缓存占用和清除按钮；
- 数据更新时间及来源状态；
- 内容和AI免责声明；
- 版本号、构建时间和提交号；
- 数据导出/导入：收藏和关注设置的JSON备份。

## 5. 功能需求

### V1-F-001 PWA外壳

- 必须提供manifest、192/512图标、主题色和standalone显示模式；
- 必须处理iOS安全区域；
- 必须提供应用内安装指引；
- Service Worker更新后提示用户刷新，不得在阅读时强制重载。

验收：iPhone Safari和Android Chrome均可添加到主屏幕，并以独立窗口启动。

### V1-F-002 静态Feed加载

- 首次请求`feed-manifest.json`；
- 验证`schemaVersion`；
- 加载`latest.json`；
- 旧版本客户端遇到不兼容schema时显示明确升级提示；
- 请求失败时读取最近缓存。

验收：在线、弱网、断网三种状态均有明确结果，不出现无限加载。

### V1-F-003 今日必读

系统根据以下可解释规则计算分数：

- 来源级别；
- 事件重要度；
- 发布时间新鲜度；
- 政策、安全、获批、关键临床结果加权；
- 同一事件多来源出现时保留主来源并增加可信度，而不是重复展示。

规则必须配置化并有单元测试。页面显示“入选理由”或对应标签。

### V1-F-004 新闻卡片与详情

卡片至少显示：中文/原始标题、来源、发布时间、地区、栏目、事件标签、两到三行摘要、是否收藏。

详情至少显示：

- 中文标题和原始标题；
- 事实摘要；
- 为什么值得关注；
- 涉及企业、药品、疾病和机构；
- 来源级别、来源名称；
- 原始发布时间和采集时间；
- AI/机器生成标识；
- 查看原文按钮；
- 原文可能无法访问的提示；
- 收藏、分享链接和返回操作。

### V1-F-005 搜索

- 对标题、摘要、实体、药品名、公司名和关键词建立前端索引；
- 支持中英文大小写不敏感匹配；
- 输入防抖；
- 空查询不运行全量扫描；
- 默认只索引最近90天；
- 结果显示命中字段和数量。

验收：在目标设备上，1万条记录的常见搜索交互无明显卡顿；如达不到，采用Web Worker或分块索引。

### V1-F-006 筛选和排序

- 支持地区、栏目、事件、疾病、来源级别多选；
- 同组内OR、不同组间AND；
- 默认按`publishedAt`降序，无发布时间时使用`collectedAt`；
- 可切换“重要度优先”。

### V1-F-007 本地收藏与关注

- 使用IndexedDB，不依赖账号；
- 存储结构必须有版本号和迁移函数；
- 支持导出、导入；
- 导入前预览数量，遇到重复ID合并；
- 清除操作二次确认。

### V1-F-008 来源配置

`config/sources.yml`每个来源至少包含：

```yaml
id: ema-news
name: European Medicines Agency
enabled: true
tier: A
type: regulator
region: EU
language: en
connector: rss
url: https://example.invalid/feed.xml
scheduleGroup: normal
legalBasis: official_api
timeoutSeconds: 20
```

真实URL由实现时依据来源官方文档填写。配置不得包含密钥。

### V1-F-009 来源连接器

首批至少实现6个稳定连接器，必须同时覆盖国内和国外，且优先选择官方来源：

- 至少2个监管/政府来源；
- 至少1个临床试验注册来源；
- 至少1个科研论文元数据来源；
- 至少1个企业/交易所公告来源；
- 其余可由产品所有者选择。

RSS、REST API和HTML公告列表分别抽象，不为每个来源复制完整抓取框架。HTML连接器仅用于无API/RSS且允许获取的公开页面。

### V1-F-010 规范化与去重

- 清除URL跟踪参数、规范协议和尾斜线；
- 标题Unicode规范化、空白合并；
- 同来源唯一键优先；
- 跨来源采用标题指纹、实体、时间窗口和事件类型综合判定；
- 不能确认时不自动合并；
- 合并记录保留全部来源链接。

### V1-F-011 翻译和摘要

采用Provider接口：

```text
TranslationProvider
SummaryProvider
```

默认必须提供无付费密钥也能运行的降级实现。可选AI Provider仅在配置密钥时启用；不得提交密钥。机器生成内容必须保存provider、model/version、prompt/template版本和生成时间。

摘要规则：

- 只陈述来源可支持的事实；
- 80至180个中文字符为目标；
- 明确区分获批、受理、推荐批准和计划申请；
- 不添加个体化医疗建议；
- 无足够内容时留空，不编造。

### V1-F-012 静态导出

- 输出必须通过JSON Schema验证；
- 保留最近90天数据，历史策略可配置；
- 单个日文件建议压缩前不超过2MB；
- 生成manifest和SHA-256；
- 构建失败不得覆盖上一版可用站点；
- 不导出第三方全文、Cookie、Token或采集调试内容。

### V1-F-013 GitHub Actions

至少包含：

1. `ci.yml`：提交时运行前后端测试、Schema验证和前端构建；
2. `collect.yml`：定时与手动触发采集，失败可重跑；
3. `deploy-pages.yml`：仅使用验证通过的产物部署Pages。

定时采集建议每4小时一次，避免对来源造成压力。Action需设置并发组，防止两个采集任务同时写数据。

### V1-F-014 来源健康状态

每次批次记录：开始/结束时间、获取数量、新增数量、去重数量、失败数量、HTTP状态分类、错误码和下次重试时间。前端只展示简化状态，不展示敏感堆栈。

### V1-F-015 内容安全和追溯

- 每条文章必须有来源和原始链接；
- C级来源不得进入今日必读；
- 解析失败内容进入构建报告，不直接发布；
- 禁止从付费墙或登录后页面获取正文；
- 测试fixture不得包含大段第三方原文。

## 6. 数据契约

必须实现：

- `contracts/article.schema.json`；
- `contracts/feed.schema.json`；
- `contracts/source-health.schema.json`；
- 至少一组有效和无效fixture；
- 前后端CI中的Schema校验。

字段以`ARCHITECTURE_AND_MIGRATION.md`为准。任何破坏兼容性的调整必须提高schema主版本并记录迁移策略。

## 7. UI与交互要求

- 设计基准宽度：360、390、430像素；
- 点击目标最小44×44 CSS像素；
- 正文默认不小于16px；
- 列表滚动位置在详情返回后恢复；
- 骨架屏只用于短暂加载，失败必须转为错误状态；
- 标签最多展示3个，其余折叠；
- 颜色不是唯一状态表达方式；
- 深色模式跟随系统并可手动覆盖；
- 所有图片必须有占位和失败状态，V1可默认不展示第三方图片。

## 8. 非功能需求

### 性能

- 首屏只加载必要JS和当日数据；
- 压缩后首屏自有资源目标小于500KB，不含按需数据；
- Lighthouse移动端Performance和Accessibility目标均不低于90；
- 慢速网络下2.5秒内显示应用外壳或明确加载状态。

### 兼容性

- 支持当前及前一个主要版本的iOS Safari；
- 支持当前及前两个主要版本的Android Chrome；
- 微信内置浏览器只保证基础浏览，并提示转到系统浏览器安装。

### 可靠性

- 单个来源失败不影响其他来源；
- 旧数据可用优先于空白页面；
- 所有定时任务可手动触发；
- 采集任务重复执行应幂等。

### 隐私

- V1不收集用户账号或个人信息；
- 收藏和关注只在本地；
- 默认不接入第三方行为分析；
- 如未来引入分析工具，必须作为新需求单独审批。

## 10. Codex实施顺序

### Epic 1：仓库与契约

- 创建目录、Maven/Vite工程和质量工具；
- 编写Schema、枚举和fixture；
- 建立CI骨架。

### Epic 2：领域与采集

- Article领域模型；
- 来源配置加载；
- RSS/REST/HTML连接器框架；
- 规范化、去重、分类、打分；
- 静态导出与健康报告。

### Epic 3：PWA用户端

- 路由、布局、主题和PWA；
- 今日、分类、详情；
- 搜索、收藏、关注、设置；
- 离线和更新体验。

### Epic 4：自动化发布

- Actions采集；
- 产物Schema校验；
- Pages部署；
- 回滚上一版产物。

### Epic 5：质量和交付

- 单元、集成和E2E；
- iOS/Android人工清单；
- README、运行手册、来源清单和限制说明。

每个Epic应单独提交和验收。禁止让Codex一次性实现V1至V3。

## 11. 完成定义

V1.0只有在以下条件全部满足时才完成：

- P0需求对应代码和测试完成；
- CI全部通过；
- GitHub Pages可访问；
- iPhone和Android真实设备验证通过；
- 定时采集连续运行至少7次；
- 未发现密钥和第三方全文进入仓库；
- README提供本地运行、手动采集、部署和回滚步骤；
- `CURRENT_PHASE.md`进度已更新；
- 已记录已知限制和进入V2前的14天观察计划。
