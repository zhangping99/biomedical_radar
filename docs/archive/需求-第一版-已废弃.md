结论：第一版最适合做“PWA 移动网页应用”，暂定名可以叫“医药雷达”。

用户在 iPhone 上用 Safari 打开网址，选择“添加到主屏幕”，以后就能像普通 App 一样点击图标启动。PWA 可以全屏运行，也支持主屏幕图标、消息推送和角标，非常适合快速验证产品。Apple 官方已经支持 iPhone 主屏幕 Web App 的独立运行和 Web Push。[Apple Web App 说明](https://developer.apple.com/videos/play/wwdc2023/10120/)

| 形式         | 上线速度 | iPhone 体验 | 主要问题                     | 建议     |
| ---------- | ---: | --------- | ------------------------ | ------ |
| PWA 网页应用   |   最快 | 很好，可添加到桌面 | 用户需要首次打开网址               | 第一版    |
| 微信小程序      |   较快 | 微信内很好     | 注册、类目资质、审核限制             | 第二阶段   |
| 原生 iOS App |   较慢 | 最好        | Xcode、开发者账号、App Store 审核 | 用户量稳定后 |
| 支付宝小程序     |   较快 | 一般        | 医药新闻与支付宝场景关联较弱           | 暂不开发   |

PWA 第一版的数据、账号和新闻处理后台，将来可以继续提供给微信小程序和 iOS App 使用，不需要重做整个系统。

## 一、产品应该怎么定位

它不应该只是“新闻列表”，而应该是：

> 把国内外分散的医药信息，整理成可信、简洁、可筛选、可订阅的行业情报工具。

每篇新闻重点回答三个问题：

1. 发生了什么？
2. 为什么值得关注？
3. 对哪些企业、医院、药品或人群有影响？

这样比简单转载新闻更有价值。

## 二、建议覆盖的内容

“国内/海外”最好作为筛选条件，而不是单独栏目。每个行业栏目都同时包含国内和海外信息。

| 栏目      | 主要内容                                        |
| ------- | ------------------------------------------- |
| 政策与监管   | 药监政策、审批规则、医保政策、集采、价格治理、DRG/DIP、FDA、EMA、WHO等 |
| 药品与研发   | 新药发现、临床前研究、Ⅰ—Ⅲ期临床、上市申请、新适应症、仿制药、生物类似药       |
| 科研与学术   | 重要论文、指南共识、科研成果、学术会议、专利、技术转化                 |
| 药企与生物科技 | 公司战略、产品管线、合作、授权交易、管理层变化、业绩、裁员和风险事件          |
| 医院与医疗服务 | 医院改革、学科建设、药品采购、医疗质量、互联网医院、智慧医院              |
| 医疗器械与诊断 | 器械审批、IVD、医学影像、手术机器人、可穿戴设备、医疗AI              |
| 资本与交易   | 融资、IPO、并购、License-in/out、基金投资、上市公司公告        |
| 医保与市场准入 | 医保目录、商业保险、药品价格、准入谈判、院内准入、零售药店               |
| 生产与供应链  | 原料药、CRO、CDMO、GMP、产能建设、进出口、供应短缺、物流           |
| 质量与安全   | 药品召回、不良反应、临床试验暂停、监管警告、数据造假、合规处罚             |
| 公共卫生    | 传染病、疫苗、慢病管理、突发公共卫生事件、疾病趋势                   |
| 前沿技术    | 细胞与基因治疗、核药、RNA药物、AI制药、脑机接口、精准医疗             |

还应该为新闻增加多维标签：

* 地区：中国、美国、欧洲、日本及其他地区
* 对象：药企、医院、科研院所、监管机构、投资机构
* 事件：获批、临床结果、融资、并购、召回、处罚、合作
* 疾病：肿瘤、心血管、免疫、神经、感染、罕见病等
* 产品：化学药、生物药、中药、疫苗、器械、诊断、医疗AI

## 三、核心功能

第一版最重要的功能：

* 今日速览：每天精选10条左右真正重要的新闻。
* 新闻流：按时间展示全部内容。
* AI摘要：用三五句话说明事件、影响和关注理由。
* 中英文处理：海外新闻自动翻译标题和摘要，同时保留原文入口。
* 分类筛选：按地区、栏目、疾病、企业和事件类型筛选。
* 搜索：搜索企业、药品、医院、政策或疾病。
* 收藏与稍后读：保存重点内容。
* 关注订阅：关注某家公司、药品、疾病领域或政策关键词。
* 重要提醒：药品获批、临床结果、召回、医保调整、重大融资等及时提醒。
* 原始来源：明确显示来源、发布时间、原文链接和采集时间。

第二阶段可以增加：

* 企业和药品档案
* 某家公司最近一年的新闻时间线
* 临床试验进展追踪
* 政策变化前后对比
* 每周、每月行业报告
* 新闻收藏夹与个人笔记
* 导出Word、PDF或Excel
* 团队共享和专题情报看板
* 行业热点趋势图
* 相同事件多来源合并，避免重复新闻

## 四、首页建议

首页不需要堆很多内容，可以设计成：

1. 今日日期和一句行业概览
2. “今日必读”5—10条
3. 政策预警和重大事件
4. 用户关注的企业、药品和疾病动态
5. 最新新闻流
6. 国内/海外及栏目快捷筛选

底部设置五个入口：

* 今日
* 分类
* 关注
* 收藏
* 我的

每张新闻卡片只显示标题、来源、时间、标签和两三句摘要，点击后再查看完整分析与原文。

## 五、新闻可信度设计

医药信息最重要的不是数量，而是可靠性。建议把来源分为三级：

* A级：监管机构、政府部门、交易所、临床试验注册平台、期刊、企业正式公告。
* B级：权威行业媒体、财经媒体、专业机构。
* C级：自媒体、社交平台和未经证实的消息，只作为线索，不直接发布。

系统还要做到：

* 优先引用原始来源
* 相同新闻自动去重
* 区分“正式获批”“申请获受理”和“拟申报”
* 区分论文、预印本和公司新闻稿
* AI生成内容明确标识
* 重大政策、临床结果和安全事件尽量人工复核
* 新闻发生更正时保留更正记录

## 六、第一版不要做什么

为了尽快上线，暂时不建议加入：

* 新闻评论区和用户发帖
* 在线问诊、用药建议或疾病诊断
* 复杂的付费会员体系
* 股票买卖建议
* 自动转载整篇新闻
* 同时开发微信、支付宝和iOS三个版本

第一版可以先做成个人或小团队使用的内部情报工具，运行稳定并验证新闻来源后，再公开推广。

## 七、技术实现建议

结合后续自动采集和AI处理需求，建议采用：

* 前端：PWA响应式网页
* 新闻采集与处理：Python
* 后端接口：Python FastAPI
* 数据库：PostgreSQL
* 定时任务：每日自动采集、去重、分类、翻译和摘要
* 管理后台：审核、修改、置顶、撤回和配置来源
* 部署：Docker，后续可迁移至国内云服务器

如果范围控制得当，界面演示版本可以很快完成；真正能够每天稳定自动更新的内部版，主要工作量会集中在新闻来源、去重、摘要质量和审核后台上。

## 八、需要提前注意的合规问题

PWA不经过应用商店审核，不代表内容没有合规要求。公开向社会提供新闻转载、聚合或传播服务，可能涉及互联网新闻信息服务许可、备案和著作权等要求；相关规定也要求转载来源可追溯并遵守著作权规则。[国家网信办《互联网新闻信息服务管理规定》](https://www.cac.gov.cn/2017-05/02/c_1120902760.htm)

因此建议：

* 前期先做个人或内部使用版本
* 使用RSS、公开API、授权数据或官方网站
* 只展示摘要、观点和原文链接，不复制整篇内容
* 不提供诊断、处方和个体化用药建议
* 公布AI摘要和免责声明
* 公开运营前进行一次专业合规审查

如果按最快路线推进，我建议下一步直接按照“个人/小团队内部版”制作产品需求文档、页面原型和第一版新闻来源清单，然后再开始开发。
